# /ship: 검토 → 테스트 → 커밋 → 푸시

아래 단계를 순서대로 진행한다. **어느 단계에서든 문제가 생기면 그 자리에서 멈추고, 커밋이나 푸시를 하지 않은 채 무엇이 문제인지 한국어로 알려 준다.** 이 프로젝트의 셸은 Windows PowerShell이므로 `npm` 대신 `npm.cmd`를 쓴다.

## 1. 올릴 것이 있는지 확인

```
git status --short
git log origin/main..HEAD --oneline
```

바뀐 파일도 없고 아직 올리지 않은 커밋도 없으면 "올릴 변경 사항이 없습니다"라고 알리고 끝낸다.

## 2. 바뀐 코드 검토

`git diff HEAD`와 새로 생긴 파일(`git status`의 `??`)을 읽고 다음을 확인한다.

- 서버를 멈추게 하거나 게임을 망가뜨릴 버그가 있는지. 특히 소켓으로 받은 데이터는 `data || {}`로 꺼내야 하고, 착수·무르기·종료 전에는 `stopClock`을 먼저 불러야 한다 (CLAUDE.md 참고).
- 디버그용 `console.log`, 임시 코드, 비밀번호나 토큰 같은 민감한 정보가 들어가지 않았는지.
- `node_modules/`나 임시 파일처럼 올리면 안 되는 파일이 포함되지 않았는지.
- CLAUDE.md의 사용자 결정(돌 소리, 알림 등)을 어기지 않았는지.

확실한 버그를 찾으면 멈추고 사용자에게 알린다. 고칠지는 사용자에게 묻는다. 사소한 스타일 문제로는 멈추지 않는다.

## 3. 테스트

```
npm.cmd test
node --check server.js
node --check public/client.js
node --check shared/renju.js
```

- `npm.cmd test`는 렌주 판정 테스트와, 실제 서버를 띄워 대국 흐름을 확인하는 서버 테스트를 함께 실행한다.
- 하나라도 실패하면 멈추고, 실패한 테스트 이름과 오류 내용을 알려 준다.

## 4. CLAUDE.md 확인

구조, 소켓 이벤트, 규칙 처리처럼 CLAUDE.md에 적힌 내용이 이번 변경으로 달라졌다면 CLAUDE.md도 함께 고친다. 바꾼 내용은 마지막 보고에 포함한다.

## 5. 커밋과 푸시

```
git add .
git commit -m "<한국어 커밋 메시지>"
git push
```

- 커밋 메시지는 무엇을 바꿨는지 한국어로 짧게 쓴다 (예: `체스 시계 방식으로 변경`). 바뀐 내용이 여러 가지면 첫 줄 아래에 빈 줄을 두고 항목을 나열한다.
- 푸시가 거절되면(원격에 새 커밋이 있으면) `git pull --rebase` 후 다시 푸시한다. 충돌이 나면 `git rebase --abort`로 되돌리고 사용자에게 알린다. `--force` 푸시는 절대 하지 않는다.

## 6. 결과 보고

한국어로 짧게 알려 준다.

- 검토에서 확인한 것과 테스트 결과 (통과 개수)
- 커밋 메시지와 커밋 해시
- 푸시 성공 여부, 그리고 Render가 몇 분 안에 자동으로 다시 배포한다는 안내
